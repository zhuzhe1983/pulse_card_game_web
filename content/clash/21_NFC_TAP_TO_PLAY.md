# 21 · 网页刷卡出牌

这是 `pcg.clash.v0` 的待试玩方案，不是已经验证的竞技规则，也不是 NFC 论坛或浏览器厂商已经规定的脉冲对决格式。费用、攻击、耐久、目标、护卫、Chain、夺舍和复活都不因刷卡改变。刷卡只是另一种把「手里的这张牌」交出去的方式，结算与拖拽出牌相同，见 `docs/20_POINTER_AND_MODES.md`。

第 03 章的玩家卡存档、英雄领取和旧的 `pcg.core.v1` 不因本章改写。本章的牌不是玩家存档。

## 1. 官方能力，和本章的设计

查阅沿用 `docs/10_SOURCES_AND_MATERIALS.md` 的 W01、W02、W03。

| 事实 | 来源 | 本章怎么用 |
|---|---|---|
| Web NFC 用 `NDEFReader` 读写 NDEF。扫描要在用户手势里调用，页面要可见，并且是安全上下文 | https://developer.chrome.com/docs/capabilities/nfc | 只做 NDEF。必须 HTTPS。必须由用户点「开始刷卡」再 `scan()`，由浏览器弹出授权 |
| 规范里的 `serialNumber` 可以是空字符串。没有通用的容量查询，也没有任意 APDU | https://w3c-cg.github.io/web-nfc/ | uid 只采用读到的 `serialNumber`。空字符串不算 uid，不编造一个 |
| 浏览器兼容性有限，不能把接口存在当成所有浏览器都能用 | https://developer.mozilla.org/en-US/docs/Web/API/Web_NFC_API | 先做功能检测。检测失败就关掉入口 |

设计决定，不是上述资料里的事实：只在 Android 上的 Chrome 提供刷卡。iOS 和其他浏览器显示「这台浏览器不能刷卡，仍可用拖拽或点选出牌」，入口禁用。拖拽、点选、双击不受影响。

## 2. 卡上的记录

卡上只写 NDEF 消息。游戏记录是一条 MIME 记录：

- `recordType` 为 `mime`
- `mediaType` 为 `application/vnd.pulse.card+json`
- 正文是 UTF-8 JSON，字段只有这些：

```json
{"v":1,"cardId":"H024","star":1}
```

`v` 必须是数字 1。`cardId` 是图册里的 rid，例如 `H024`，由网页对照 `content/clash_roster_96.json` 找到 `template_id` 再出牌。`star` 可以省略；写了就必须和这张 rid 的星级一致。不认识的字段不单独构成另一种牌，但正文必须能解析成这个对象。

uid 不是写进 JSON 的字段。uid 就是这次读取事件里的 `serialNumber`。它为空时，界面写「这张卡没有可读序号」，去抖改为按 `cardId` 在 1.5 秒内忽略重复，并说明两张相同的卡这时无法区分。

可选第二条记录是一条 URL，指向配置里的 Wiki 卡页 `{wikiBase}/cards/{cardId}`。没有配置 `wikiBase` 就不写这条，也不编造正式域名。URL 记录不能代替上面的 MIME 记录。

## 3. 读到之后怎么分类

| 类别 | 判断 | 界面 |
|---|---|---|
| 已初始化的 PULSE 卡 | 消息里有一条上述 MIME，`v` 为 1，JSON 可解析，`cardId` 和可选 `star` 对得上图册 | 「读到 {中文名}」 |
| 空白卡 | 没有 NDEF 记录，或消息为空 | 「这是空白卡，可以初始化」 |
| 陌生内容 | 有记录，但没有合法的 PULSE MIME，或 `v` 不是 1，或 JSON 损坏，或 `cardId`／`star` 对不上 | 「这张卡不是脉冲对决的出牌记录」 |
| 读取失败 | 超时、硬件错误、会话中断 | 「没读到卡，请再贴一次」 |
| 权限拒绝 | 用户拒绝授权，或页面不是 HTTPS | 「没有刷卡权限。可以改用拖拽或点选」 |

读取失败不能当成空白卡。权限拒绝不能当成陌生内容。

## 4. 空白卡初始化

只在对局外的初始化入口做。顺序是：

1. 用户从图册里选一个 `cardId`。
2. 界面列出中文名、费用、攻击、耐久和星级，用户再点一次「写入这张卡」。
3. 写入第 2 节的消息。
4. 立刻再读一遍。MIME 正文和刚写入的 JSON 不一致，就报「写入后校验失败」，这张卡不能当成已初始化。

空白卡没有第二次确认。陌生内容绝不静默覆盖。覆写陌生内容要先显示「卡上已有其他内容」，用户再点一次「仍然覆写」才写入。用户不点，卡上的字节保持原样。

玩家存档那种大快照不在这里写。写失败不把卡解释成已经可用。

## 5. 对局里刷卡

只有轮到己方的主阶段才出牌。对方回合、对方正在行动、热座还没确认换人，都只提示「现在不能替这一方操作」，不出牌。

刷到一张已初始化的卡，等于从手牌打出对应的 `template_id`。手里没有这张牌，提示「手里没有这张牌」，不扣电，不移牌。手里有，费用、插入位置、目标和红圈 × 都与拖拽出牌相同：

- 不需要目标的主控，按双击规则排到己方最右。
- 需要目标或插入缝的牌，刷卡之后进入和拖拽相同的箭头、绿色合法标记、红色圆圈加 ×。合法松手才提交一次。取消、空白、非法松手都不扣电，不消耗攻击次数，不改归属和血量。
- 小印复活厚壳仍是按钮 `复活厚壳 · 1电`，刷卡不能把厚壳插到别的位置。

同一次提交不能既当刷卡又当双击。同一 uid 在 1.5 秒内再次读到，忽略后面的几次，避免贴着不放打出两张。uid 为空时，按上一节用 `cardId` 去抖。

## 6. 验收

Android Chrome、HTTPS、用户点过「开始刷卡」并授权之后，能读到 H024 并在手里有新细条时打出一张。iOS 和不支持的浏览器只看到禁用说明，拖拽和点选仍可完成教学局。

空白卡要经过选牌和确认才写入，读回不一致就报错。陌生内容不点「仍然覆写」就不会被改掉。对方回合刷卡不出牌。手里没有的牌不扣电。非法目标出现红圈 ×，取消不扣电。同一 uid 连读不会出两张。
