# PULSE · 触卡对决

一个可以直接用静态服务器运行的 NFC 卡牌对战游戏。用你提供的 M5Stack 卡图，组合十张卡，在前后两排部署角色，通过留牌、停牌和技能选择赢下三局内的对决。

**在线试玩：** <https://zhuzhe1983.github.io/pulse_card_game_web/>

**运行游戏不需要 npm、不需要后端，也不需要读卡器。** `dist/index.html` 内嵌页面、样式、游戏代码以及全部 44 张 PNG 素材；下载后可以离线玩电脑对战或本地双人。WebRTC 联网时才会进行相应的网络连接。

## 先运行起来

解压源码包，进入项目文件夹，运行：

```bash
cd dist
python3 -m http.server 8000 --bind 127.0.0.1
```

在浏览器打开 **http://localhost:8000**。Windows 上若命令是 `python` 或 `py`，用相应命令替换 `python3`。

如果只下载了单文件 HTML，把它放在一个文件夹里，启动同样的静态服务器，再打开该文件。若文件名不是 `index.html`，地址应带文件名，例如 `http://localhost:8000/pulse-card-game.html`。

建议先用桌面 Chrome/Edge。直接双击 HTML 可能能看到页面，但文件地址下的存储与硬件权限行为因浏览器而异，正式试玩用 localhost 静态服务器更容易复现。

### 五分钟试玩

1. 点击 **开始一场练习**，系统会准备模拟玩家身份，立即进入训练场。
2. 选一张手牌，选择允许的前排或后排；技能需要目标时再点战场上的目标，最后点击部署。
3. 留意对手的战力和手牌数量。点击 **本局停牌 PASS**，可以放弃继续投入这一局，把手牌留给下一局。
4. 返回大厅，打开 **模拟卡盒**，先刷玩家卡，再点一张模拟英雄卡，体验每日盲盒。
5. 到 **我的卡牌** 调整十张编队。标准对战可以借用所有卡，不必先把角色抽齐。

## 三种玩法

| 模式 | 如何开始 | 保存与交接 |
|---|---|---|
| 训练场 | 点击开始练习 | 电脑会考虑留牌与停牌，只读取自己的手牌及公开战场；本地对局可刷新后继续 |
| 面对面对决 | 准备两位不同玩家，选择各自编队 | 一台设备轮流操作，每回合交接屏遮住手牌；刷正确玩家卡或点击明确标注的模拟刷卡入口才能揭牌 |
| 远程交锋 | 双方登录不同玩家，交换邀请与回复连接码 | 浏览器 WebRTC DataChannel；房主裁决，双方版本与卡包必须一致；刷新或重建连接不恢复原在线对局 |

### WebRTC 连接步骤

1. 双方打开同一版本，登录各自的玩家身份并保存编队。
2. 房主进入 **远程交锋**，点击 **我是房主 · 创建邀请**，复制完整的 `PCGRTC1.` 邀请码给朋友。
3. 朋友选择 **我有邀请 · 加入**，粘贴邀请，点击生成回复码，将回复发回房主。
4. 房主粘贴朋友的回复，接收后等待两端自动进入战场。

没有公共房间服务器；连接码不是短房间号。两个标签页测试时，也必须选择不同玩家。每个标签页的当前玩家独立记录，但同源标签页共享本地收藏与绑定数据库。

**网络设置**可选择默认公网 STUN、仅本地/局域网或自定义 `iceServers`。部分 NAT、运营商或企业网络需要自备 TURN 中继；静态页面无法保证任意两台设备都能直连。详细消息格式与排障见 [NETWORK.md](docs/NETWORK.md)。

## 玩法规则

- 每套牌恰好 **10 张不同的卡**，至少 6 张角色。开局十张全部在手，局间不补牌。
- 每回合出一张牌或 PASS。每局每人最多出 5 张，战术牌也计入；出满或没牌时自动停牌。
- 角色部署在前排或后排。两排战力合计决定本局胜负，排位影响卡片限制和联结技能。
- 一旦 PASS，本局不能继续出牌；对方可以继续。双方停牌后结算，已出角色弃置，未出的手牌带入下一局。
- 胜局得 2 分，平局双方各 1 分。先到 4 分结束；否则第三局结束后比较积分，允许整场平局。
- 上局胜者下局先手；平局则轮换先手。初始先手由开局随机种子决定。

技能只保留四种易于跨设备实现的操作：无技能、给己方已在场角色 `+2`、给敌方角色 `−2`、部署时另一排有友军则自身 `+2`。**稳定**角色的战力不会改变；**护盾**抵消首次干扰。角色降到 0 战力仍留在战场。

抽卡不会增加战力。赢面来自如何用完十张牌，以及何时停止投入一局。

## 玩家卡、英雄卡与收藏

**01–09 是玩家卡的九种外观；10–22 是十三位角色的素材。** 玩家卡面编号不是账号编号，每位玩家都有独立随机 UUID；相同卡面可以属于不同玩家。

首次读取没有 PULSE 身份记录的实体卡时，可以在本机选择登记为玩家卡，或登记为盲盒/指定角色的英雄卡。登记保存于浏览器，不会自动改写实体卡。读卡器只能读卡号或数据，不能从 UID 推断卡面上印的是哪张图片。

先刷玩家卡登录，再刷英雄卡领取：

- 每位玩家对同一英雄卡，每天最多领取一次，按 **UTC+8 零点**换日。
- 盲盒从 13 位角色中按内容包权重抽取；指定角色卡固定获得登记的角色。
- 重复角色增加 10 碎片；50 碎片可解锁该角色墨色外观，数值保持不变。
- 全部 13 位角色和 2 张战术都可在标准对战中借用。收藏与竞技入场资格分开，没抽到也能公平组牌。
- 对战中不会开盲盒。可识别的英雄卡可以作为选中相应手牌的快捷入口，不能凭空生成手牌。

模拟卡盒遵守相同每日领取规则，用于没有硬件时测试。

### NTAG215 能写，但不是安全认证卡

NTAG215 的 504 字节用户读写区适合保存玩家 UUID、卡面、版本等轻量 NDEF 身份。它的 32 位密码限制读写，不等于加密身份认证；本版不会配置密码或永久锁位。[NXP 数据手册](https://www.nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf)

在 **读卡器 → 写入当前玩家身份** 中，只有连接了具备写入能力的适配器才会启用按钮。确认后会替换目标卡的原有 NDEF，必须使用专用于本游戏的卡。写后再次刷卡核验。

**卡内只存身份，完整收藏和进度存在浏览器。** 把身份卡带到另一台设备会识别同一个玩家 ID，但不会自动带走本机收藏；迁移使用 JSON 备份。

## 外部读卡器支持范围

| 设备/连接方式 | 本版支持 | 说明 |
|---|---|---|
| USB/蓝牙键盘式 UID 读卡器 | 读取 UID | 点击卡号框再刷卡并回车；需输出十六进制原始字节顺序 |
| **M5Dial USB NFC 桥** | **Web Serial 读 UID + PULSE 身份 NDEF** | ESP-IDF 固件把 M5Dial 变成 USB 刷卡器；配网页烧录器 `dist/flash.html`。详见 `firmware/m5dial_nfc_bridge` |
| PCG vendor USB 协议桥 | WebUSB 读卡；可选 NDEF 读写 | 需要实现 `pcg.reader.v1` 固件，并提供 class `0xFF` bulk IN/OUT |
| ESP32 + PN532 串口桥 | Web Serial 读卡 | 附带 UID 只读 Arduino 例程；固件尚未编译/实机验证，需核对芯片、引脚及库版本 |
| Android 手机内置 NFC | 读取 NDEF、写入玩家身份 | 需要支持 Web NFC 的浏览器、NDEF 标签和安全上下文 |
| ACR122U 等通用 CCID/PCSC 读卡器 | 无通用直连驱动 | 不能把 WebUSB 连接按钮当作 CCID 驱动；需另做本机桥接或专用支持 |
| iPhone/iPad 网页 | 可体验游戏、模拟刷卡及支持的浏览器联网 | 本版不承诺 Safari/iOS WebUSB 或 Web NFC 读卡 |

普通网页不能通过 WebUSB 接管所有 USB 接口；智能卡 class `0x0B` 属于受保护类别。Grove 也是接线接口，不保证所有 NFC 模块拥有相同芯片与协议。[WebUSB 规范](https://usb.spec.whatwg.org/#has-a-protected-interface-class) · [Chrome Web NFC](https://developer.chrome.com/docs/capabilities/nfc)

硬件连接要求 localhost 或可信 HTTPS。手机通过普通局域网 HTTP 地址访问电脑，通常不具备这些能力所需的安全上下文。协议、写卡格式、固件用法见 [READERS.md](docs/READERS.md)。

## 存档、迁移与版本

在 **读卡器 → 备份与迁移** 导出或导入 JSON。备份包含本机所有玩家、收藏、卡片绑定及本地数据库；当中可能包含本地对局双方的隐藏手牌，应作为自己的存档保存，不要当作公开对战记录分享。

同一浏览器、同一来源下会使用已有进度；写入玩家身份卡不会覆盖本机收藏。不同浏览器、隐私窗口、设备、域名或端口可能使用不同存储。例如 `localhost:8000` 与 `localhost:8080` 不共享进度。清除站点数据前先导出备份。

导入会合并玩家和绑定，识别可证明先后的存档分支，保留已知较新的进度；不能证明先后的分支会拒绝覆盖。导入不会把备份中的进行中对局替换为当前对局，也不会复制源设备的 `device_id`。版本或精确卡包哈希不符时拒绝导入。

本版保留 **`pcg.core.v1` 核心规则**，使用素材专用卡包 **`m5.web.assets.v1`**。网页存档是 `pcg.web.local` / JSON 备份，联网是 `pcg.web.v1` / WebRTC JSON；它们不是旧版二进制 PCSV/NFC 存档与传输包的直接替代。硬件客户端须实现相同配置或显式转换，不能仅凭规则名相同就宣称完全互通。详细兼容要求见 [WEB_PROFILE.md](docs/WEB_PROFILE.md)。

## 开发与测试

页面运行不需要构建工具。修改模块后可以重新生成单文件：

```bash
python3 tools/build.py
```

Node 仅用于运行无依赖的软件测试：

```bash
node tests/engine.test.cjs
node tests/store.test.cjs
node tests/readers.test.cjs
node tests/rtc.test.cjs
node tests/network-game.test.cjs
```

引擎测试使用原 Python 参考对局与摘要向量，检查规则一致性；存档测试包含重复领取、日期回拨、写入失败与冲突导入；读卡和网络模块另有边界测试。真实浏览器与硬件的最终验收范围以随包验证记录为准；模拟传输测试不代表任意 USB 硬件或公网 NAT 已通过。

主要文件：

| 路径 | 用途 |
|---|---|
| `dist/index.html` | 可独立运行的完整页面，素材全部内嵌 |
| `src/app.js`、`src/style.css`、`src/template.html` | 界面、交互和页面模板 |
| `src/engine.js` | 确定性规则、状态投影、幂等裁决与电脑策略 |
| `src/store.js` | 本地玩家、抽取、存档和迁移 |
| `src/readers.js` | USB/串口/NDEF/键盘读卡适配器 |
| `src/rtc.js`、`src/network-game.js` | 手动信令、DataChannel 和房主裁决会话 |
| `content/pack.json`、`content/presentation.json` | 数值与卡包；显示名称、素材编号及文案 |
| `asset/card/`、`asset/char/` | 用户提供的 22 张完整卡图与 22 张角色图 |
| `docs/` | 规则接口、网页配置、联网和读卡协议 |
| `firmware/` | M5Dial NFC·USB 桥（WS1850R/MFRC522，ESP-IDF）与 PN532 桥固件 |

素材来自用户提供的 [pulse_card_game_prompt/asset](https://github.com/zhuzhe1983/pulse_card_game_prompt/tree/main/asset)，本包保留原图。涉及公开发布或素材再分发时，遵循原素材权利人的授权范围。

## 当前边界

这是面向朋友的本地优先试玩版：每日限制依赖本机记录与设备时钟，无法阻止修改客户端、存档或身份；联网房主持有完整权威状态，不具备竞技服务器的防作弊能力。在线房间只在当前页面会话中存在，刷新后需要重新开局。本地练习/双人对局可以继续，但目前每个来源只保留一场本地对局，多个标签页不要同时开始不同的本地对局。

这些限制不会影响先验证最关键的问题：**十张牌、跨局留牌和刷卡招募，是否形成了值得再来一局的节奏。**
